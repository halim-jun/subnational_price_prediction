# Codex Instructions

This repository is an East Africa food price prediction project. It combines food price, climate, vegetation, conflict, food security, macroeconomic, and geospatial data to model subnational food prices, mainly for Kenya and Somalia.

## Current Repository Shape

- `src/data_pipeline/`: data processing pipelines.
  - Important submodules include `spi`, `macro`, `fews_net`, `wfp`, `crop_mask`, `night_lights`, `dynamic_world`, `spatial_weighting`, and `merge`.
- `src/model/`: training scripts.
  - `train_model_stcv.py`: primary spatio-temporal cross-validation workflow.
  - `train_holdout.py`: 2024+ holdout evaluation.
  - `train_model.py`: older baseline workflow.
- `src/analysis/`: diagnostic and exploratory analysis scripts.
- `src/notebook/`: notebooks and notebook-exported scripts.
- `src/dashboard/`: FastAPI backend and Next.js frontend dashboard.
- `scripts/`: utility scripts, including static data export.
- `data/`: local raw and processed datasets.
- `artifact/`: model outputs, metrics, predictions, and plots.
- `docs/`: project documentation and reference material.
- `deploy/`: Cloudflare/static dashboard deployment files.

## Working Rules

- Treat this as a data science repository where silent data loss, leakage, or broad row dropping can invalidate results.
- Before changing modeling or preprocessing logic, inspect the relevant input columns, date handling, spatial keys, and missing-value behavior.
- Preserve forecasting integrity:
  - do not use future target values as features;
  - lag exogenous features according to the prediction horizon when the existing workflow does so;
  - keep temporal and spatial validation boundaries intact.
- Prefer small, targeted edits over broad refactors.
- Do not rewrite notebooks unless explicitly asked; prefer editing `.py` scripts or notebook-exported scripts.
- Do not delete or regenerate large data/artifact files unless the user explicitly asks.
- Be careful with generated directories such as `node_modules`, `out`, `__pycache__`, and `.DS_Store`; avoid touching them unless required.

## Common Commands

Set up Python:

```bash
source venv/bin/activate
pip install -r requirements.txt
```

Run model workflows:

```bash
python src/model/train_model_stcv.py
python src/model/train_holdout.py
python src/model/train_model.py
```

Run dashboard locally:

```bash
uvicorn src.dashboard.api.main:app --reload --port 8000
cd src/dashboard/frontend && npm run dev
```

Build static dashboard prototype:

```bash
python scripts/export_static_data.py
cd src/dashboard/frontend
NEXT_PUBLIC_STATIC_MODE=true npm run build
```

Run quality checks when relevant:

```bash
python src/data_pipeline/merge/check_merge_quality.py
python src/data_pipeline/merge/check_admin_coverage.py
pytest
```

## Data Notes

- Canonical merged modeling data is `data/processed/subnational_merged_v3_KEN_SOM.parquet`.
- This parquet is generated by `src/data_pipeline/merge/run_subnational_merge.py`, which calls `src/data_pipeline/merge/subnational_merger.py`.
- Current merge inputs include:
  - price data from `data/worldbank_imputed_price_data/WLD_RTFP_mkt_2026-01-13.csv`;
  - ACLED from `data/raw/acled/Africa_aggregated_data_up_to-2026-01-03.xlsx`;
  - FLDAS from `data/fldas/processed/EastAfrica_FLDAS_Fixed_2007_2025.csv`;
  - vegetation from `data/vegetation/processed/EastAfrica_Vegetation_Indices_2007_2025.csv`;
  - climate indices from `data/climate_indices/processed/Climate_Indices_2007_2025.csv`;
  - crop mask aggregates from `data/crop_mask/admin_mapped/admin_agg.parquet`;
  - WorldPop rasters from `data/population_worldpop/`;
  - Admin2 boundaries from `data/geoboundaries/`.
- GeoBoundaries files under `data/geoboundaries/` are the administrative boundary reference.
- Country codes generally use ISO3, such as `KEN`, `SOM`, and `ETH`.
- Artifacts are split by workflow:
  - `artifact/model_output_stcv/`
  - `artifact/model_output_holdout/`
  - `artifact/model_output/`

## Dashboard Data Flow

- Local dashboard frontend: `src/dashboard/frontend/`.
- Local dashboard backend: `src/dashboard/api/`.
- At runtime, the FastAPI backend loads:
  - `artifact/model_output_holdout/holdout_predictions.parquet`;
  - `artifact/model_output_holdout/holdout_metrics.csv`;
  - `artifact/model_output_holdout/holdout_per_admin_*.csv`;
  - `artifact/model_output_stcv/cv_aggregated_metrics.csv`;
  - `artifact/model_output_stcv/cv_fold_results.csv`;
  - `artifact/model_output_stcv/cv_feature_group_importance.csv`;
  - `artifact/model_output_stcv/cv_metrics.json`;
  - `data/processed/subnational_merged_v3_KEN_SOM.parquet`;
  - `data/geoboundaries/gb_KEN_ADM2.geojson` and `data/geoboundaries/gb_SOM_ADM2.geojson`.
- `scripts/export_static_data.py` exports the same FastAPI responses to `src/dashboard/frontend/public/data/` for static prototype builds.
- `deploy/cloudflare/` contains a separate static deployment copy. Do not assume it is the same app as `src/dashboard/frontend/`.

## Dashboard Metrics Workflow

- Treat dashboard performance metrics as evaluation outputs, not display-only UI data.
- Before changing dashboard metric aggregation, confirm whether the values come from:
  - holdout test artifacts under `artifact/model_output_holdout/`; or
  - spatio-temporal CV artifacts under `artifact/model_output_stcv/`.
- The current performance dashboard should show holdout test metrics from `holdout_predictions.parquet` and related holdout outputs unless explicitly changed.
- Keep target, horizon, country, date, and admin keys intact when aggregating metrics. Do not mix Kenya and Somalia evaluation results into a single headline metric unless the UI labels it clearly as combined.
- For dashboard metric aggregation changes, add or update focused pytest coverage that verifies the expected grouping and metric calculations.
- After backend/API metric changes, run the relevant pytest target, for example `pytest tests/test_dashboard_metrics.py`.
- After frontend performance page changes, run `cd src/dashboard/frontend && npm run build`.
- If the static dashboard prototype is affected, run `python scripts/export_static_data.py` and verify the relevant JSON under `src/dashboard/frontend/public/data/`.

## Cleanup Guidance

- Safe cleanup candidates are generated caches/build outputs: `node_modules/`, `.next/`, `out/`, `__pycache__/`, `*.pyc`, and `.DS_Store`.
- Do not delete data or artifact directories only because they are not used by the dashboard. Some are needed to reproduce the merged dataset or model artifacts.
- `artifact/model_output/` is a legacy baseline output and is not read by the current dashboard, but keep it unless the user explicitly wants to remove legacy results.
- Large source/intermediate folders such as `data/night_lights/`, `data/raw/wfp/`, `data/fewsnet/`, and older merged parquet files may be unused by the current dashboard path, but they are cleanup candidates rather than guaranteed deletions.

## Style

- Python files should use `snake_case` names and existing local patterns.
- Prefer `pandas`, `geopandas`, `rasterio`, and existing helper functions over ad hoc parsing.
- Use logging or explicit errors for suspicious data conditions instead of silently passing.
- If a command cannot run because local data, credentials, or network access are missing, report that clearly.
